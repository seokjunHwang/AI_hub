## 1. 환경 세팅

**준비물 4가지** — Node 18 이상(`node -v`) · git(`git --version`) · 작업할 저장소(`git status`) · Claude 계정(구독 또는 API 키)

| 단계 | 명령 | 성공 기준 |
|---|---|---|
| 설치 | `npm i -g @anthropic-ai/claude-code` | `claude --version` 출력 |
| 실행·로그인 | 저장소 안에서 `claude` | 브라우저 승인 후 프롬프트 |
| 확인 | "이 저장소 뭐하는 프로젝트인지 한 줄로" | 파일 읽고 답함 |
| 첫 5분 | `/init` · `/model` · `/permissions` · 첫 실전 요청 | `CLAUDE.md` 생성 |

- **저장소 안에서 시작**해야 «작업 범위»가 정해진다. 아무 폴더나 안 됨
- 자주 막히는 곳: `npm ERR! EACCES`(sudo 말고 nvm) · Node 16 이하 · 브라우저 안 열림(URL 직접) · 사내 프록시(`ANTHROPIC_BASE_URL`) · 한글 깨짐(UTF-8)

**완료 판정 5개** (다 체크되면 설치 끝)
```
□ claude --version 이 버전을 출력한다
□ 저장소 안에서 claude 가 뜨고 로그인이 끝났다
□ 읽기 요청 하나에 답이 왔다
□ CLAUDE.md 가 생겼고, 한 줄 고쳐서 커밋했다
□ 편집 요청 때 확인을 물어보는 걸 봤다
```

**왜 터미널인가** — 성능이 아니라 **접근권**. ① 내 디스크를 그대로 봄(업로드 없음) ② git 위에서 돎(되돌리기가 git) ③ **훅으로 내 코드가 끼어든다** ← CLI만 가능

## 3. 하네스 엔지니어링

> 프롬프트 엔지니어링 = 더 잘 **말하는** 법 / 하네스 엔지니어링 = 말이 **지켜지게** 만드는 법
> 한 문장: **«규칙을 프롬프트에 적는 대신, 검사하는 코드로 옮긴다»**

### 훅 5지점

```
[SessionStart] ─▶ [PreToolUse] ─▶ 실행 ─▶ [PostToolUse] ─▶ [Stop]
  규칙 주입        도구 차단              상태 알림        응답 반려
                                              └▶ [SubagentStop] 보고 반려
```
초록=넣는 자리 / 주황=막는 자리. **Stop이 가장 강함** — 응답 반려 시 턴이 끝나지 않음 → "다시 쓰라"가 요청이 아니라 **조건**이 된다.

### 규칙 4층 (아래가 위를 이긴다)

```
1  ECC 플러그인          남이 검증한 기본기
2  ~/.claude/CLAUDE.md   개인 작업 방식
3  저장소 CLAUDE.md       이 저장소에서만 참인 것 + 사고 기록
4  .claude/hooks/ + lefthook   실제 검사 코드 (훅 6종 + pre-commit 8종)  ◀ 강제력
```
**«저장소에 커밋된 규칙이 메모리를 이긴다»** — 두 세션이 같은 메모리의 다른 시점 사본으로 정반대로 알았던 사고 이후.

### 가드 7종 — 전부 사고에서 나왔다 (미리 설계한 것 없음)

| 가드 | 지점 | 막는 것 |
|---|---|---|
| `routing-guard` | PreToolUse | 메인에서 남의 담당 기획 파일 수정 |
| `ds-guard`/`ds-session` | PreToolUse·SessionStart | 실측 근거 없이 화면 그리기 |
| `honorific-guard` | Stop·SubagentStop | 반말 응답 → 턴을 끝내지 않음 |
| `ctx-relay-guard` | PostToolUse·Stop | 컨텍스트 50% 초과 후 인계 카드 없이 종료 |
| `shared/main-index-guard` | PreToolUse·pre-commit | 남의 staged 파일 위 커밋 |
| `ds-newscreen-guard` | pre-commit | 근거 인용 없는 새 화면 커밋 |
| `stale-artifact-guard` | pre-push | 낡은 빌드 산출물 푸시 (68커밋 뒤처진 트리에서 39커밋 분이 사라질 뻔) |

### 가드 3원칙

1. **정말 깨졌는지 «먼저» 확인** — 게이트를 먼저 돌리면 깨지지도 않은 걸 보고 "못 잡는다"로 오독
2. **정탐·오탐 둘 다 본다** — 오탐이 정탐 실패보다 비싸다 (막힌 사람이 게이트를 끄면 정탐도 사라짐)
3. **«무엇을 볼 수 없는지»도 적는다** — 「빌더 출력 == 셸」만 보다가 둘이 똑같이 깨진 경우를 통과시킴

**가드도 낡는다** — 워크트리의 훅 사본이 19커밋 뒤처져 정상 커밋을 거부. **재는 자[尺]가 낡은 경우**는 「세는 법」 규칙으로 안 걸린다.

### 차단은 «거부»가 아니라 «전환»

담당 slug · 워크트리 경로 · 다음 절차까지 붙여야 우회하지 않는다. **방해물이 되는 순간 사람은 훅을 끈다.**

### 권한 모드 4종과 순서

| 모드 | 동작 | 언제 |
|---|---|---|
| `default` | 쓰기·명령마다 확인 | 처음 며칠 |
| `acceptEdits` | 파일 편집 자동승인, 명령은 확인 | **실무 기본값** |
| `plan` | 읽기만 하고 계획 수립 | 큰 작업 착수 전 |
| `bypassPermissions` | 확인 없이 진행 | **가드를 갖춘 저장소에서만** |

```
default ─▶ acceptEdits ─▶ (가드 완비 후) bypassPermissions
```
확인을 없앤다 = **판단을 사람에서 코드로 옮긴다**. 옮길 코드가 없으면 그냥 무방비.

⚠ **기본 확인을 줄일수록 «무엇을 읽히는가»가 위험해진다** — 외부 저장소·이슈 본문·웹 페이지는 **전부 프롬프트 주입 경로**다.

## 4. 기획 운영 6원칙 — 전부 «기억을 신뢰 대상에서 빼는» 장치

| 원칙 | 기억에 맡기면 | 하네스가 대신 |
|---|---|---|
| **01 정본** | "아마 저기 적혀 있을 거예요" | SSOT 파일 지정 → 가드가 그 파일만 검사 |
| **02 파장** | "관련 문서도 같이 고쳤던 것 같은데" | Impact Matrix 조회 → 고정 순서 → 체크리스트 |
| **03 병렬** | "저 파일 아무도 안 만지겠지" | `routing-guard` 가 담당 아닌 쓰기를 거부 |
| **04 인계** | "전에 얘기했으니 알겠지" | `handoff.py` 가 근거 없는 인계문 전송 거부 |
| **05 근거** | "전수 확인했습니다" | 세는 법 3요소 병기 |
| **06 컨텍스트** | "어디까지 했더라" | `ctx-relay-guard` 가 카드 없는 종료 반려 |

**01 정본** — 같은 사실이 두 곳에 적히면 반드시 갈라진다. 정본이 한 곳이면 **가드를 걸 수 있다**(검사 대상이 생김). 예: 데이터모델 1곳 · 내비 정책 §1 · `tokens.py` · `routing.json`

**02 파장** — 스펙 한 줄이 IA·플로우·데이터모델·정책을 움직인다. 고정 순서:
`arch-ia → user-journey → user-flow → data-model → ai-data-spec → screen-*.policy`
계층이 위→아래로 흐르므로 데이터모델을 먼저 고치면 IA와 어긋난 채 굳는다.

**03 병렬** — 브랜치는 한 번에 하나, **워크트리는 디렉터리 25개**라 세션 25개가 진짜 동시에 돎.
> 사고: 진입 시점 `git status` 는 깨끗했다. **동시성 문제는 관측 이후에 생긴다** — "지금 깨끗하다"는 안전 신호가 아니다.

**05 근거 — 안 센 값을 적지 않는다** (가장 여러 얼굴로 데인 병. AI로 일할 때 특히 — **그럴듯한 문장이 관측처럼 읽히기 때문**)

| 병 | 적힌 것 | 실제 |
|---|---|---|
| 안 센 값 | "컨트롤러 46개 전수 확인" | 세어본 적 없음. 실제 58개 |
| 좁은 검색 | "잔존 0건" | 변종 검색 누락, 16파일에 남아 있었음 |
| 어긋난 단위 | "읽는 유일한 폴더" | 엔티티 단위로만 유일. 필드 단위로는 다른 폴더도 읽음 |

→ 「전수 확인」류에는 **세는 법 셋**을 병기: **무엇을 · 어느 단위로 · 어떻게(도구·검색어)**
> 세는 값과 세는 법 중 오래 쓰이는 건 **세는 법**. 값은 다음 커밋에 낡는다.

**06 컨텍스트 50%**
```
50% 도달 ─▶ 하던 한 가지만 마감 ─▶ 인계 카드 ─▶ /clear ─▶ 새 세션이 카드만 이어받음
```
50%인 이유: **아직 스스로 무엇을 넘길지 고를 수 있는 시점.** 자동 압축은 아무 데서나 끼어든다.

| 카드에 쓰는 것 | 쓰지 않는 것 |
|---|---|
| 지금 하던 일 (끝나지 않은 한 가지) | 끝난 일 · 오늘 한 일 목록 |
| 다음 한 걸음 (행동 하나) | 계획 전체 · 로드맵 |
| 근거 (커밋 SHA · 확인 날짜) | 기억으로 쓴 상태 주장 |
| 일부러 안 넘기는 것 | |

끝난 일은 넘기지 않는다 — 중요하면 커밋·문서·티켓 코멘트에 있어야 한다.

## 5. 회의 → 문서 파이프라인

```
기획 미팅 ─▶ 전사 ─▶ 회의록 .md ─▶ ■ 멈춤 ─▶ 반영 대상 번호 제시 (1·2·3…)
 구두 결정  transcript  위키 커밋                      │
                                            사람이 고름 "1번 3번만"
                                                       ▼
                                              다섯 벌 작성 + 연쇄
```

사람이 한 일 = **회의하고 녹음 버튼 누른 것.**

세 가지 이득:
1. **구두 결정이 증발하지 않음** — 문서로 안 옮겨진 결정은 «없던 일». 전사가 남으면 "정했는데 안 옮겼다"는 걸 안다
2. **결정 출처가 소급됨** — 각 절에 «어느 회의의 어떤 발언» → "이거 왜 이렇게 됐죠?"에 답이 있다
3. **한 번 멈춤** — 회의에서 나온 말이 전부 결정은 아니다

> 요점은 «AI로 문서를 뽑았다»가 아니라 **구두 결정이 그날 안에 파일이 됐다**는 것. 사흘 뒤 정리하면 기억이지 기록이 아니다.

## 6. 문서 다섯 벌 = 질문 다섯 개

### 전체 흐름 — 어디서 하네스가 잡는가 (1부와 2부가 만나는 지점)

```
요청 한 줄 ─▶ 라우팅 ─▶ 착수 전 조사 ─▶ 다섯 벌 작성 ─▶ 정합성 검증 ─▶ 커밋·인계
 회의·티켓    내 일인가   정본·선행결정    1→2→3→4→5      빠진 것 찾기   재생성·푸시
                 │            │              │               │            │
              routing-      ds-guard      impact 조회    policy       pre-commit
              guard         실측 근거      연쇄 대상      assertion    근거 없으면
              남의 폴더면    주입          추출           항목 누락      거부
              차단                                       검사
```

회색(판단)은 사람, 초록(작성)은 다섯 벌, **주황은 전부 코드가 잡는 자리**. 절차의 각 단계마다 대응하는 가드가 하나씩 있다는 게 요점이다.


| # | 문서 | 답하는 질문 | 없으면 |
|---|---|---|---|
| 1 | `spec-{feature}.md` | **무엇을** 만드는가 (범위 + «안 하는 것») | 범위가 매 회의마다 다시 열린다 |
| 2 | `*.jsx` | **어떻게 보이는가** | 사람마다 다르게 상상 |
| 3 | `screen-*.policy.md` | **언제 무엇이** 일어나는가 | 구현이 매 분기마다 물어봄 |
| 4 | `arch-*.md` | 다른 것과 **어떻게 이어지는가** | 옆 기능과 모순 |
| 5 | `TC_*.md` | **됐는지 어떻게 아는가** | "된 것 같다"로 끝남 |

**1→5 = «바꾸기 비싼 것 → 싼 것».** 거꾸로 시작하면 앞이 바뀔 때마다 뒤를 통째로 다시 쓴다.

### 각 벌에서 깨지는 지점

- **spec** — 버전 번호 충돌. 이력표는 최신이 위라 검색 결과만 보고 정하면 중복 → **이력표 머리를 직접 열 것**
- **jsx** — 대응 앱 화면 URL 먼저 특정 → 실측 → **토큰만(hex 금지)** → 헤더에 근거·계측일.
  ⚠ **bypass 함정**: `python3`·`sed`·heredoc 으로 고치면 편집 도구 감시만으론 가드가 안 뜬다 → **셸 명령까지 감시 대상**
- **policy** — 화면 기획과 **항상 동시에**. 나중에 쓰면 그림만 남고 조건이 사라짐
- **arch** — 내 폴더 밖으로 나가는 유일한 문서. 순서 건너뛰기 · 중복 반영 · 뒤처진 채 푸시가 사고 3종
- **tc** — 정책 항목 1개 = TC 1개. **값이 아니라 불변식.** 형태로 적으면 그 형태만 확인하고 통과 → 같은 규칙 깨는 다른 형태에 도달

### 정책서 필수 7항목 (+AI 4)
```
1 화면 접근 조건 (권한 + 상태 «둘 다»)
2 모든 UI 요소 표시/비표시 조건
3 로딩 · 빈 상태 · 에러 상태
4 모든 버튼의 트리거 → 결과
5 API 호출 시점 · 파라미터 · 실패 처리
6 역할별 뷰 차이
7 엣지케이스 3개 이상
+AI  생성버튼 활성조건 · 확인/미확인 전환 · 실패 fallback · 데이터 출처 표시
```
판정은 «잘 썼다»가 아니라 **«빠진 게 있다/없다»** → 그래서 검사기가 볼 수 있다.

## 7. 기반 문서 6종 — 앞이 남긴 질문에 뒤가 답한다

제품 전체에 하나씩. 기능 기획은 여기에 **«등재»되는 방식으로 합류**.

```
① 유저 저니 맵    누가·무엇이 아픈가   ─ 페인·순간 ─▶
② 유저 플로우     어떤 경로로 움직이나  ─ 화면목록·분기 ─▶
③ IA             어떤 구조로 놓이나   ─ 계층·경로 ─▶
④ 와이어프레임     대충 어떻게 생겼나   ─ 배치·구성요소 ─▶
⑤ 데이터 인벤토리  무슨 데이터를 만지나  ─ 필드·민감도 ─▶
⑥ AI 데이터 스펙   AI는 뭘 받고 뭘 내나
```

**거꾸로 만들면** — IA부터 그리면 "이 메뉴가 왜 있는지"를 아무도 답 못 하고, 데이터 인벤토리부터 만들면 **안 쓰는 필드를 정성껏 정의**하게 된다.

- **유저 플로우** — 정상 경로만 그리면 절반. **실패·만료·재시도 분기를 같은 그림에** → 이게 정책서 엣지케이스와 TC가 된다 (매번 새로 발명하지 않음)
- **IA** — 붙일 자리가 없으면 그건 화면이 아니라 **구조 결정이 남은 것**. 좌측 메뉴의 권위 정의도 여기 (화면 코드의 메뉴 배열은 전부 사본)
- **와이어프레임** — **실측을 넣지 않는다.** 넣으면 JSX와 «두 벌의 진실»이 생긴다
- **데이터 인벤토리** — 수집 3분류(직접입력/자동수집/AI생성). **«민감» 칸 하나가 권한·감사·삭제 정책 셋을 끌고 온다** → 비워두지 않는다
- **AI 데이터 스펙** — 공통 규약을 맨 앞(수동 트리거만 · 미확인/확인 전환 · fallback 필수 · 모델 라우팅 · 프롬프트 버전관리). 구현과 대조 못 한 항목은 **«미대조»로 박아둔다 — 추측해서 고치지 않는다. 틀린 확신보다 표시된 공백이 낫다**

## 8. 착수 전 조사 3분 — 네 곳

```
① 폴더 정본        기존 spec·policy → 있으면 «신규»가 아니라 «업데이트»
② 전역 문서        기능 결정처럼 보이는 게 실은 전역 결정인 경우가 많다
③ 관련 티켓 코멘트  문서엔 없지만 남이 카드에 적어둔 것
④ 그 결정을 받은 사람  대화에만 있을 수 있다 (검색이 아니라 물어보기 → 잘 빠진다)
```

### 「미확인」과 「미조사」를 가른다 ← 가장 중요한 구분

- **미확인** = 찾아봤고 없었다 / **미조사** = 안 찾아봤다
- 섞어서 「미정」이라 쓰면 **받는 쪽이 이미 있는 답을 다시 만든다**

```
확인   : 정책 §1.2.4 · 스펙 §6.1 을 찾았고 없었다 (2026-08-25)
미조사 : 코어 데이터모델 · 관련 티켓은 보지 않았다
```
