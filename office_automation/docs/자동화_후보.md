# 자동화 대상 업무 후보

선정 기준: **빈도 × 소요시간 × 표준화 가능성**. 셋 다 높은 것부터 만든다.

---

## A. 회의 (핵심 축)

| # | 업무 | 입력 → 출력 | 난이도 |
|---|---|---|---|
| A1 | **회의록 정리** | 녹음 → STT → 요약·결정사항·액션아이템 → Notion 회의록 + Slack 요약 | 중 |
| A2 | **액션아이템 이슈화** | 회의록 액션 → GitHub Issue 자동 생성 (담당자·마감·라벨) | 중 |
| A3 | **액션 추적** | 다음 회의 전, 지난 액션의 완료 여부 자동 점검 → Slack 리포트 | 하 |
| A4 | **회의 전 브리핑** | 캘린더 일정 → 참석자·지난 회의록·관련 이슈 모아 5분 전 DM | 하 |
| A5 | **결정 로그(Decision Log)** | 모든 회의의 "무엇을 왜 결정했나"를 검색 가능한 DB로 축적 | 중 |

> A5가 시간이 갈수록 값이 커진다. 3개월 뒤 "이거 왜 이렇게 했지?"에 답하는 자산.

**주의**: 자동화의 진짜 병목은 요약 품질이 아니라 **액션아이템의 담당자·마감이 회의에서 확정되지 않는 것**이다. AI도 없는 정보는 못 만든다. → 회의 마지막 3분에 "액션 확인" 순서를 넣는 것이 자동화 성공률을 가장 크게 올린다.

## B. 보고·문서

| # | 업무 | 입력 → 출력 |
|---|---|---|
| B1 | **주간보고 초안** | GitHub 커밋·PR + Notion 태스크 + Slack 스레드 → 주간보고 초안 |
| B2 | **고객 제출용 변환** | 내부 기술 문서 → 발주처 톤 보고서 (docx / HTML) |
| B3 | **용어집 자동 축적** | 회의록·문서에서 신규 용어 추출 → 용어집 갱신 (온보딩 자산) |
| B4 | **문서 영향 분석** | 참조 문서가 바뀌면 영향받는 산출물 목록 알림 |
| B5 | **제안서·견적 초안** | 요구사항 메일 → 과거 유사 제안서 검색 → 초안 |

| # | 업무 | 입력 → 출력 |
|---|---|---|

| C3 | **이슈 트리아지** | 신규 이슈 → 라벨·담당자 추천 + 중복 탐지 |
| C4 | **스탠드업 초안** | 어제 커밋·PR → 각자 daily 초안 |

## D. 커뮤니케이션

| # | 업무 | 입력 → 출력 |
|---|---|---|
| D1 | **Slack 스레드 요약 → 아카이브** | 긴 논의 스레드 → Notion 정리 (휘발 방지) |
| D2 | **메일 분류·답장 초안** | 수신 메일 → 유형 분류 + 답장 초안 + 첨부 추천 |
| D3 | **미답변 감지** | 나에게 온 질문 중 24h 무응답 스레드 알림 |
| D4 | **일정 조율** | 메일·Slack의 일정 제안 → 캘린더 빈 시간 대조 → 회신 초안 |

## E. 시각화 (HTML 뷰어 / Artifact)

| # | 업무 | 결과물 |
|---|---|---|
| E1 | **액션 칸반** | 회의록 액션을 담당자·마감별 대시보드로 publish |
| E2 | **프로세스 다이어그램** | 회의에서 나온 프로세스를 mermaid로 자동 작도 |
| E3 | **프로젝트 타임라인** | 마일스톤·의존성 시각화 |
| E4 | **회의 히스토리 뷰어** | 주제별로 언제 무슨 결정이 있었는지 타임라인 |

> Artifact는 링크 하나로 공유되므로, 팀에 "보여주는" 산출물은 전부 여기로 몰 수 있다.

## F. 정기 실행 (cron / loop)

| 시점 | 작업 |
|---|---|
| 매일 아침 | 오늘 일정 + 미완료 액션 + 밤새 온 이슈·메일 브리핑 |
| 회의 5분 전 | A4 브리핑 |
| 매주 금요일 | B1 주간보고 초안 |
| 매주 월요일 | 미완료 액션 리마인드 |

---

## 만드는 순서 (추천)

```
1차   A1 회의록 정리          ← 체감 효과 가장 큼. 여기서 파이프라인 골격이 잡힌다
2차   A2 + E1 액션 이슈화·칸반  ← 회의록이 "읽는 문서"에서 "돌아가는 시스템"으로
3차   B1 주간보고             ← A1/A2 데이터가 쌓이면 거의 자동으로 나온다
4차   A3 + F 정기 실행         ← 사람이 트리거하지 않아도 도는 단계
5차   나머지는 실제 불편한 것 순서로
```

---

## 설계 원칙

1. **처음엔 초안까지만.** 자동 게시(쓰기 권한)는 신뢰가 쌓인 뒤. 초안 → 사람 확인 → 게시
2. **Skill로 절차를 고정.** 프롬프트를 매번 쓰지 않는다. 포맷·톤·금칙을 Skill 문서에 박아둔다
3. **입력을 표준화하는 게 모델을 바꾸는 것보다 효과적.** (회의 액션 확인 순서, 파일명 규칙)
4. **출력은 항상 원본으로 되돌아갈 링크를 포함.** 요약만 남으면 검증이 불가능해진다
5. **기밀 데이터 경로를 먼저 정한다.** 회의 녹음·환자 관련 언급·계약 내용 → 외부 전송 여부 정책 결정
