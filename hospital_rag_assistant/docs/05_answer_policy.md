# 05. 답변 정책 · 금칙 · 에스컬레이션

이 문서는 코드보다 먼저 병원과 합의해야 하는 문서다. 여기서 합의된 것만 구현한다.

## 1. 리스크 티어 정의

### TIER-A — 생성 절대 금지
의학적 판단·해석이 개입되는 모든 질의.
- 증상에 대한 원인·병명 추정 ("이런 증상이면 뭔가요?")
- 약 복용 가능 여부·용량·상호작용
- 검사 결과 수치 해석
- 치료 방법 선택, 수술 여부 판단
- 타 병원·타 의료진과의 비교 평가

→ 동작: 고정 문구 출력 + 진료 예약 또는 상담 연결. **검색·생성 모두 수행하지 않는다.**

### TIER-B — RAG 생성 허용 (주 대상)
병원이 문서로 확정한 사실 안내.
- 진료시간, 휴진, 진료과·의료진 안내
- 예약·변경·취소 절차, 앱 사용법
- 위치·주차·교통·편의시설
- 검사 전 준비사항 ← **단, 원문 그대로 출력(verbatim)**
- 입퇴원 절차, 증명서 발급, 수납·보험 서류
- 건강검진 프로그램 안내

### TIER-C — 시나리오/소형 응답
인사, 잡담, 챗봇 사용법, 명확한 단일 기능 호출.

## 2. Verbatim 필수 항목 (재표현 금지)

LLM이 한 글자도 바꿀 수 없는 내용. 검색 후 원문 삽입만 허용.
- 금식·복약 중단 등 검사 전 지침
- 금액, 수수료, 진료비
- 전화번호, 팩스, 주소, 계좌
- 법적 고지, 동의 문구
- 시간(진료시간, 접수 마감)

이유: 이들의 오류는 즉시 실질적 피해가 된다. 자연스러움을 포기할 지점이 여기다.

## 3. 금칙 표현

- 확신 어투: "괜찮습니다", "문제없습니다", "안전합니다", "이상 없습니다"
- 판단 어투: "~인 것 같습니다", "~일 가능성이 높습니다" (증상·질환 문맥)
- 처방 어투: "복용하세요", "중단하세요", "드셔도 됩니다"
- 근거 없는 일반화: "보통 ~합니다", "대부분 ~입니다"
- 병원 정책에 없는 예외 창작: "특별히 요청하시면 ~"

## 4. 응급 인터럽트

감지 시 파이프라인 전체를 중단하고 전용 응답만 출력.
- 트리거 예: 흉통, 호흡곤란, 의식 저하, 마비, 다량 출혈, 경련, 음독, 자살·자해 표현
- 응답: 119 / 응급실 안내 + (자해 표현 시) 정신건강 상담 전화 안내
- 이 경로는 **재현율(recall) 우선**. 오탐(false positive)은 허용한다.

## 5. 에스컬레이션 규칙

| 상황 | 처리 |
|---|---|
| 근거 검색 실패 | "확인이 어렵습니다" + 시나리오 메뉴 또는 상담 연결 |
| 검증 게이트 2회 실패 | 답변 폐기 → 상담 연결 |
| TIER-A 판정 | 고정 문구 + 진료/상담 안내 |
| 개인 진료정보 요구 | 앱 인증 화면 안내 (챗봇이 직접 처리하지 않음) |
| 사용자가 3턴 내 같은 질문 반복 | 즉시 상담 연결 (이해 실패로 간주) |
| 민원·불만 표현 감지 | 즉시 상담 연결 |

## 6. Abstain 문구 원칙

사과 반복·책임 회피 인상을 주지 않게, **다음 행동을 항상 제시**한다.

- 나쁨: "죄송합니다. 답변할 수 없습니다."
- 좋음: "그 내용은 제가 확인된 안내로 갖고 있지 않아요. 상담원 연결 또는 대표번호(00-000-0000)로 안내받으실 수 있습니다."

## 7. 로그·개인정보

- 사용자 발화 내 개인정보는 저장 전 마스킹 (이름/생년/연락처/환자번호)
- 외부 LLM API 전송 전 마스킹 적용 여부는 위탁 계약·병원 보안정책에 따름 → 확인 필요 항목
- 보관 기간·접근 권한은 병원 정책에 위임, 문서로 명시
