# 02. 연습 기획 — 단계별 실험 (P0 ~ P7)

각 단계는 **혼자 돌려볼 수 있는 실험**이고, **회의에서 보여줄 산출물**이 하나씩 나온다.
실제 시나리오 데이터가 없어도 P0~P5는 공개 자료로 전부 연습 가능하다.

---

## P0. 코퍼스 실험장 만들기
**목표** 병원 안내 도메인 문서셋을 손으로 만들어 본다. RAG 품질의 80%는 여기서 결정된다.

- 공개된 병원 안내 페이지(진료시간, 오시는 길, 주차, 증명서 발급, 검진 안내) 30~50건 수집 → `data/raw`
- 표·목록이 많은 문서를 어떻게 텍스트화할지 실험 (표를 문장으로 풀 것인가, 그대로 둘 것인가)
- 청킹 전략 3종 비교: ① 고정 길이 ② heading 기반 ③ QA 단위 재작성
- **산출물** `data/corpus/*.jsonl` + 청킹 전략별 장단점 1페이지

> 배우는 것: 병원 문서 특유의 함정 — 예외조항("단, 소아는…"), 부서별 상이한 운영시간, 개정일자.
> 청크가 예외조항을 잘라먹으면 그게 곧 오답이 된다.

---

## P1. 검색 베이스라인 & 한국어 임베딩 벤치
**목표** 생성 이전에 **검색이 맞는지** 먼저 증명한다.

- BM25(형태소 토크나이저) / Dense(임베딩 2~3종) / Hybrid(RRF) / +Rerank 4개 조건 비교
- 지표: Recall@5, MRR, nDCG@10
- 한국어 특수 케이스 테스트: "엠알아이"vs"MRI", "이비인후과"vs"귀코목", 오탈자
- **산출물** 조건별 성능표 + "우리 도메인엔 hybrid가 필수/불필요" 결론

> 배우는 것: 병원 도메인은 고유명사·약어 비중이 높아 sparse가 의외로 강하다. 이걸 수치로 확인한다.

---

## P2. 시나리오 → 코퍼스 브릿지 + 리스크 라우터
**목표** 이 프로젝트의 정체성. 시나리오를 근거로 재활용하고, 위험 질의를 생성 경로에서 격리한다.

- 가상의 시나리오 트리(20~30 노드) 직접 작성 → `docs/01` 스키마로 평탄화
- `question_forms` LLM 증강 (노드당 발화 변형 10개 생성)
- 리스크 티어 분류기 구현: 규칙(키워드) + LLM 분류 하이브리드
- 티어 분류 평가셋 100문항 (A/B/C) → **TIER-A를 B로 오분류하는 건 치명적 실패로 별도 집계**
- **산출물** 라우터 confusion matrix, TIER-A 누락률 0 달성 여부

---

## P3. 근거 강제 생성 + Abstain
**목표** "모르면 안 답하는" 동작을 프롬프트와 임계값으로 만든다.

- 근거강제 프롬프트 설계: 근거 블록 외 사용 금지, 문장별 `[출처ID]` 태깅, 부족 시 부족 선언
- `verbatim_required` 분기 구현 (원문 그대로 vs 재표현)
- Abstain 트리거 3종 실험: ① rerank 점수 임계 ② LLM 자기판정 ③ 둘의 결합
- **답할 수 없는 질문 50문항**을 평가셋에 의도적으로 포함 (미커버 의도, 개인정보 요구, 타 병원 질의)
- **산출물** 임계값-abstain율 곡선, 오답률과의 트레이드오프 그래프

> 배우는 것: abstain 임계를 올리면 오답은 줄지만 커버리지가 죽는다. 이 곡선이 발주처와 협의할 실제 재료다.

---

## P4. 검증 게이트 (Guardrail Layer)
**목표** 생성 후 한 번 더 잡는다. 여기가 발주처가 제일 좋아하는 부분.

- claim 분해 → 근거와 entailment 판정 (지지/모순/무관) → unsupported 있으면 차단
- 규칙 필터: 진단·처방·용량 표현, 단정 어투("괜찮습니다", "문제없습니다")
- 숫자/날짜/전화번호/금액 **원문 문자열 일치 검사** (LLM이 가장 잘 틀리는 지점)
- PII 탐지·마스킹 (입력·로그 양방향)
- **산출물** 게이트 통과/차단 사례집, 게이트 단독으로 잡아낸 할루시네이션 목록

---

## P5. 평가 하네스 & 회귀 CI
**목표** 품질을 "느낌"이 아니라 "수치"로 말한다. → 상세 설계는 `04_eval_plan.md`

- 골든셋 200~300문항 구축 (답변가능 / 답변불가 / 위험질의 / 멀티턴 4종 혼합)
- 자동 채점: 정답성, unsupported claim rate, citation precision, abstain 적정성
- 프롬프트·모델·임계값 변경 시 자동 회귀 실행
- **산출물** 평가 리포트 템플릿, 조건별 성능 비교 대시보드

---

## P6. 미커버 질의 학습 루프
**목표** 운영에 넘긴 뒤에도 스스로 좋아지는 구조.

- abstain·상담원 이관 로그 수집 → 임베딩 클러스터링 → 빈발 미커버 의도 Top-N 리포트
- 운영팀에게 "이 3개 주제만 문서 써주면 문의 12% 흡수됩니다" 형태로 제출
- **산출물** 주간 갭 리포트 자동 생성 스크립트

> 이건 기술 산출물이면서 동시에 **영업 산출물**이다. 발주처에 제일 잘 팔린다.

---

## P7. (조건부) 증상 → 진료과 안내
**목표** 최고 난도·최고 리스크. P0~P6이 안정된 뒤에만 착수.

- 트리아지가 아니라 **"진료과 안내"** 로 프레이밍 (판단하지 않고, 병원이 정한 매핑표를 안내)
- 병원 승인 매핑표를 코퍼스로 사용, LLM 추론 금지
- 응급 키워드 인터럽트 필수, 고정 disclaimer 강제
- **산출물** 리스크 분석서 + 병원 의료진 검수 요청안

---

## 권장 순서와 기간 감각

```
P0 ─ P1 ─ P2 ─ P3 ─ P4 ─ P5 ─ P6 ─ (P7)
└ 여기까지가 "RAG 할 수 있음" 증명
        └ 여기까지가 "안전하게 할 수 있음" 증명  ◀ 발주처 승인 지점
                        └ 여기까지가 "운영 가능함" 증명
```

먼저 P0+P1을 붙여 **작동하는 데모**를 만들고, P3+P4를 붙여 **못 답하는 데모**를 만들어라.
회의에서 임팩트가 큰 쪽은 후자다. "이 질문엔 일부러 답하지 않습니다"를 보여주는 순간 논쟁이 끝난다.
