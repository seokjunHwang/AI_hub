# 00. 문제 정의와 요구사항

## 1. 현재 상태 (As-Is)

- 병원 앱 내 상담 챗봇이 **시나리오 트리 기반**으로 동작
- 사용자는 버튼/정해진 분기를 따라가며, 최종적으로 사전 작성된 답변을 받음
- 장점: 답변 100% 통제, 할루시네이션 0, 법적 리스크 낮음
- 문제:
  1. **자연어 질문이 안 통한다** — 사용자는 "MRI 전에 밥 먹어도 되나요?"라고 묻는데, 챗봇은 분기 선택을 요구
  2. **커버리지 절벽** — 시나리오에 없는 질문은 전부 실패 (또는 상담원 연결)
  3. **체감 지능 부재** — "AI인지 아닌지 모르겠다"
  4. **유지비** — 새 질문 유형마다 사람이 분기를 그려야 함

## 2. 이해관계자 요구

| 주체 | 진짜 요구 |
|---|---|
| 병원(발주) | 틀린 안내로 인한 민원·법적 리스크 0. 특히 의학적 판단 금지 |
| 앱 운영팀 | 상담원 인바운드 감소, 시나리오 유지보수 부담 감소 |
| 사용자 | 물어본 걸 물어본 방식대로 답해주기 |
| 개발사(우리) | 위 셋을 동시에 만족시키는 구조 + 그걸 증명할 수치 |

## 3. To-Be 요구사항

### 기능 요구
- FR1. 자연어 단문 질의로 병원 안내 정보 응답 (진료시간, 위치, 예약 절차, 검사 준비, 서류 발급, 수납 등)
- FR2. 모든 응답에 **출처 근거**를 내부적으로 보유, 필요 시 UI 노출
- FR3. 근거를 못 찾으면 **답하지 않고** 시나리오/상담원으로 이관 (graceful abstain)
- FR4. 멀티턴 문맥 유지 (대명사·생략 복원)
- FR5. 답변 불가/미커버 질의는 로그로 축적 → 코퍼스 보강 루프

### 비기능/안전 요구
- NFR1. **진단·처방·복용량 판단 절대 금지** (의료법 리스크). 해당 의도는 탐지 즉시 이탈
- NFR2. 응급 키워드(흉통, 호흡곤란, 의식저하, 자살 등) 감지 시 즉시 응급 안내로 인터럽트
- NFR3. 검색 근거에 없는 문장(unsupported claim) 출력률 목표 **< 1%**
- NFR4. 개인정보(환자명, 진료기록, 연락처) 프롬프트/로그 유입 차단 및 마스킹
- NFR5. 응답 지연 P95 목표 3초 이내
- NFR6. 모든 답변 변경은 회귀 평가셋 통과 후 배포 (CI)

## 4. 성공 기준 (증명해야 하는 숫자)

| 지표 | 목표 |
|---|---|
| 커버리지 (자연어 질의 중 정상 응답률) | 시나리오 대비 +X%p |
| Unsupported claim rate | < 1% |
| 오답 중 "확신하며 틀린" 비율 | ~0 (틀릴 상황이면 abstain 해야 함) |
| Abstain 정확도 (답할 수 있는데 회피한 비율) | < 10% |
| 상담원 이관율 | 하락 |

핵심: **정답률보다 "틀린 답을 내지 않음"을 먼저 증명**해야 발주처가 생성형을 허가한다.

## 5. 스코프 밖

- 진료 예약 트랜잭션 실행 (조회/안내까지만, 실행은 기존 앱 기능)
- 개인 진료기록 조회형 응답 (인증·권한 이슈, 별도 과제)
- 증상 기반 진료과 추천 → **P7에서 별도 검토**, 기본 스코프 제외
