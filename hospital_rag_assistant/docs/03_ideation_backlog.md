# 03. 아이데이션 / 백로그

로드맵(P0~P7) 밖의 아이디어. 가치 대비 난이도로 분류.

## A. 지금 당장 값이 나오는 것 (빠르고 임팩트 큼)

**A1. 시나리오 커버리지 갭 분석 (코드 없이도 가능)**
기존 상담 로그/문의 텍스트를 클러스터링해서 "현재 시나리오가 못 받는 질문 유형"을 지도로 만든다.
→ 개발 착수 전에 제출할 수 있는 첫 산출물. 이걸로 프로젝트 필요성을 스스로 증명한다.

**A2. 근거 카드 UI 제안**
답변 밑에 "이 안내는 [진료안내 > 검사 준비] 문서 기준입니다 (2026-03 개정)" 카드를 붙인다.
할루시네이션 리스크에 대한 **UX 차원의 방어**. 사용자 신뢰가 올라가고, 틀렸을 때 추적 가능해진다.
기술 비용 거의 0, 발주처 체감 효과 큼.

**A3. "AI 같다"를 만드는 최소 개입**
사실을 바꾸지 않고도 체감 지능을 올리는 3가지:
- 되묻기(clarifying question): "어느 진료과 예약이신가요?" ← 시나리오 분기를 자연어로 위장
- 후속 제안: 답변 후 "관련해서 주차 안내도 필요하신가요?"
- 사용자 어휘 반영: "엠알아이"로 물으면 "MRI(엠알아이)"로 답
→ 이 셋만으로 사용자 인식이 크게 바뀐다. 리스크는 0.

## B. 중기 (기술 난도 중, 차별화 큼)

**B1. Verbatim 슬롯 템플릿**
답변을 [고정 문구] + [재표현 가능 문구] 슬롯으로 쪼갠다.
금식 시간·금액·연락처는 슬롯에 원문 그대로 주입, 연결 문장만 LLM이 쓴다.
→ 자연스러움과 정확성을 동시에 얻는 가장 실전적인 트릭.

**B2. 질의 재작성(Query Rewriting) 전용 단계**
멀티턴·구어체·오탈자를 self-contained 표준 질의로 변환. 검색 성능이 가장 크게 오르는 저비용 개선.

**B3. 개정일자 인식 검색**
병원 문서는 개정이 잦다. 청크에 `effective_date`를 넣고, 만료 문서는 검색에서 감점/제외.
→ "작년 진료시간을 안내한 사고"를 구조적으로 막는다. 병원 도메인 특화 포인트.

**B4. 부서/캠퍼스 스코핑**
같은 질문의 답이 부서·건물마다 다르다. 사용자 컨텍스트(선택한 진료과)로 검색을 필터링.
→ 안 하면 "맞는 문서인데 틀린 답"이 계속 나온다. 실무에서 가장 흔한 실패 원인.

**B5. 답변 캐시 + 승인 워크플로**
자주 나오는 질의의 생성 결과를 사람이 한 번 승인하면 캐시로 고정.
→ 시간이 갈수록 시스템이 "확정 답변 기반"으로 수렴한다. 비용·지연·리스크 동시 감소.
발주처가 가장 안심하는 구조.

## C. 장기 / 연구성

**C1. Self-RAG / 검색 필요성 판단** 검색 없이 답할 수 있는 질의를 스스로 걸러 지연 절감
**C2. 다국어(영/중) 안내** 외국인 환자 대응. 코퍼스는 그대로, 출력 언어만 전환 — 번역 정확성 검증 필요
**C3. 음성 인터페이스** 고령 환자 접근성. STT 오인식이 검색에 주는 영향 실험
**C4. 온프렘 sLM 전환 검토** 병원 보안 정책상 외부 API 금지 시나리오 대비. 품질 하락폭 측정
**C5. 시나리오 자동 생성** 코퍼스에서 시나리오 트리를 역생성해 운영팀 유지보수 부담 제거

## D. 리스크 백로그 (반드시 문서로 남길 것)

- D1. 의료법상 의료행위·진단 해석 경계 → 법무 검토 필요 항목 리스트업
- D2. 개인정보/민감정보 처리 근거 (외부 LLM API 전송 가능 여부, 위탁 계약)
- D3. 로그 보관 정책 (프롬프트에 환자 발화가 남는다)
- D4. 오답 발생 시 책임 소재 및 사후 절차(정정 공지, 로그 추적)
- D5. 모델 버전 변경 시 재검증 의무 (프로바이더 업데이트로 답변이 바뀔 수 있음)

> D는 발주처 회의에서 우리가 먼저 꺼내면 신뢰를 얻고, 저쪽이 먼저 꺼내면 방어에 몰린다.
