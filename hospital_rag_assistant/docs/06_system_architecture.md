# 06. 시스템 아키텍처

## 0. 설계 결정 요약 (먼저 읽을 것)

| 결정 | 내용 | 이유 |
|---|---|---|
| **DB를 나누지 않는다** | 정형·비정형·시나리오·가드레일·평가를 **단일 PostgreSQL + pgvector**의 스키마로 분리 | pgvector는 Postgres 확장이다. 별도 벡터DB로 분리하면 메타데이터 pre-filter(부서·캠퍼스·개정일)를 SQL WHERE로 못 걸고 정형 테이블과 조인이 끊긴다. **필터링 가능한 검색이 이 도메인의 생명** |
| **숫자는 벡터로 찾지 않는다** | 진료시간·금액·연락처는 정형 테이블 → **파라미터화 SQL 템플릿** | 벡터 검색으로 시간표를 찾으면 틀린다. Text-to-SQL도 금지(생성 리스크) — LLM은 슬롯 추출만 |
| **시나리오 히트는 생성을 건너뛴다** | L0 고신뢰 매칭 시 승인된 원문 그대로 출력 | 가장 안전하고 가장 빠르다. 생성·검증 비용 0 |
| **스트리밍을 포기한다** | 검증 게이트 통과 후 일괄 출력 | 사후 검증과 토큰 스트리밍은 원리적으로 상충. 병원 도메인에선 검증이 우선 |
| **모든 단계 fail-closed** | 가드레일 모델 오류·타임아웃 = 생성 포기, 시나리오 폴백 | 방어 장치가 죽었을 때 무방비 통과는 최악의 실패 모드 |
| **CRAG의 웹검색 폴백 제거** | 검색 실패 시 웹으로 나가지 않고 쿼리 재작성 재검색 → abstain | 일반 의학 웹문서는 코퍼스 사용 금지 등급 |

## 3. 지연 예산 (P95 3초 목표)

```
G0 입력정제        10ms  |#
G1 병렬 판정      150ms  |####
Q  질의정규화     300ms  |########
G2 티어라우팅     150ms  |####
R0 시나리오조회    50ms  |#
R1 검색           250ms  |#######
   CRAG 그레이더  300ms  |########
   (재검색 1R)   +550ms  |##############        <- 최대 1라운드만 허용
GEN 생성         1000ms  |##########################
G5 검증           500ms  |#############
                -------
   정상 경로     2410ms  (재검색 없음)
   재검색 1R     2960ms  (한계선)
```

설계 함의

- **CRAG 재검색은 1라운드로 하드 제한.** 2라운드는 예산 초과 → abstain이 더 낫다.
- G1은 3개 모델 병렬. 순차 실행 시 예산 파괴.
- G1/G2 판정과 R1 검색의 **투기적 병렬 실행**(검색을 미리 시작, 차단 판정 시 폐기)으로 400ms 절감 가능. 단 TIER-A 질의에도 검색이 도는 셈이라 감사 로그에 "검색 수행됨"이 남는다 → 병원과 합의 필요. 기본값은 순차.
- 조기 종료 경로(차단·응급·시나리오 히트)는 200~400ms. 트래픽의 상당 비율이 여기서 끝나므로 평균 지연은 훨씬 낮다.

## 4. 가드레일 모델 서빙

| 항목 | 설계 |
|---|---|
| 서버 | vLLM. 8B 2개 + 2.1B 1개 |
| VRAM | 8B×2 bf16 약 32GB + 2.1B 약 4.5GB → **48GB 1장(L40S/A6000) 권장** |
| 절감안 | AWQ/GPTQ 4bit 시 약 12GB. 또는 siren-8b를 규칙 조기종료 뒤 조건부 호출 |
| 호출 | `max_new_tokens=1`, greedy. 출력 1토큰이라 배치 효율이 매우 높다 |
| 임계 조정 | 라벨만 쓰지 말고 첫 토큰 로짓에서 `<SAFE>` vs `<UNSAFE-*>` **확률을 뽑아 로그에 남기고 임계 튜닝** |
| 온프렘 | Apache-2.0 → 병원 내부망 배포 가능. **외부 API 금지 정책에도 생존** |

> 병원 보안정책상 외부 LLM API가 막히면, 가드레일 층은 이미 온프렘이므로 생성 LLM만 교체하면 된다. 층을 이렇게 나눈 이유다.

## 5. 환경 분리

```
DEV      단일 Postgres 컨테이너 + 합성 데이터 + 양자화 가드레일 (로컬)
STAGING  운영 코퍼스 사본 + 골든셋 회귀 CI 게이트
PROD     온프렘 Postgres(HA) + 가드레일 GPU 노드 + 생성 LLM(내부/외부)
```

릴리즈 게이트: `TIER-A leak = 0` AND `unsupported claim < 1%` AND `numeric fidelity = 100%` ([docs/04](04_eval_plan.md))
