# 08. 가드레일 설계

정책(무엇을 막을지)은 [docs/05](05_answer_policy.md). 이 문서는 **어떻게 막을지**의 기술 설계다.

## 0. 원칙

1. **단일 방어선 금지.** 가장 강한 탐지기도 놓친다 (kanana-safeguard-prompt recall 0.748 → 인젝션 4개 중 1개 통과). 층을 겹친다.
2. **fail-closed.** 어느 층이든 오류·타임아웃이면 생성을 포기하고 시나리오로 폴백한다. 가드레일이 죽었을 때 무방비 통과가 최악의 실패 모드다.
3. **차단은 규칙, 판단은 모델.** 응급·PII·금칙어처럼 명시 가능한 건 규칙으로 (결정적·감사 가능·0ms). 의도 판단만 모델에 맡긴다.
4. **모든 결정을 확률과 함께 기록.** 라벨만 남기면 임계값을 못 튜닝한다. `guard.decision_audit.score`에 `<SAFE>` vs `<UNSAFE-*>` 확률을 남긴다.
5. **재현 가능성.** 모델버전·프롬프트버전·코퍼스버전 스탬프 없이는 3개월 뒤 감사에 대응할 수 없다.

## 1. 7층 가드레일 스택

```
                              사용자 발화
                                   |
  L0  입력 위생        규칙        정규화 · PII 마스킹 · 길이제한
                                   |
  L1  공격 탐지        모델        safeguard-prompt-2.1b   A1 인젝션 / A2 리킹
                                   |
  L2  유해·응급        규칙+모델   응급 키워드 매처 + safeguard-8b  S1~S7
                                   |
  L3  권한·티어        모델+정책   safeguard-siren-8b  I1~I4 + 도메인 인텐트 분류
                                   |
  L4  근거 제약        검색설계    소스 화이트리스트 · 개정일 · 스코프 · 점수 임계
                                   |
  L5  생성 제약        디코딩      출력 스키마 강제 · verbatim 슬롯 주입
                                   |
  L6  출력 검증        모델+규칙   entailment · 숫자 exact match · 금칙어 · 재적용
                                   |
  L7  행동 제약        코드        side effect 금지 · rate limit · 반복 감지
                                   |
                              최종 응답
                                   |
        모든 층 -> guard.decision_audit (결정·라벨·확률·버전·지연)
```

각 층이 막는 공격/실패가 다르다.

| 층 | 막는 것 | 못 막는 것 |
|---|---|---|
| L0 | 인코딩 우회, PII 유출, 토큰 폭탄 | 자연어 우회 |
| L1 | 인젝션·시스템프롬프트 탈취 | 25%는 통과 (recall 0.748) |
| L2 | 유해 발화, 응급 상황 놓침 | 정상 문장으로 위장한 위험 질의 |
| L3 | 의료 판단 요구, 개인정보 요구 | 경계 케이스 과탐/미탐 |
| L4 | 없는 사실, 만료 정보, 타 부서 정보 | 근거는 맞는데 오독하는 생성 |
| L5 | 자유 서술, 숫자 창작 | 근거 오독 |
| L6 | **위 전부의 잔여 오류** | 검증기 자체 오류 |
| L7 | 부작용 실행, 남용 | — |

> L6이 최종 방어선이다. 여기가 실질적으로 unsupported claim rate를 결정한다.

## 2. Kanana Safeguard 통합 설계

### 2.1 모델 배치와 우리 정책의 매핑

| 모델 | 라벨 | 우리 정책 매핑 | 액션 |
|---|---|---|---|
| `kanana-safeguard-prompt-2.1b` | `A1` 프롬프트 인젝션 | 시스템 우회 시도 | 차단 + 반복 카운트 |
| | `A2` 프롬프트 리킹 | 내부 정보 노출 시도 | 차단 |
| `kanana-safeguard-8b` | `S6` 자살·자해 | **NFR2 응급 인터럽트** | 즉시 응급/상담 안내 |
| | `S1~S5` | 유해 발화 | 정중 거절 |
| | `S7` 허위정보 | (출력측에서 활용) | 경고 로그 |
| `kanana-safeguard-siren-8b` | **`I2` 전문조언(의료·법률·세무·금융)** | **TIER-A 의료 판단 금지** | 생성 금지 + 진료 안내 |
| | `I3` 개인정보 | 개인 진료정보 요구 | 앱 인증 화면 안내 |
| | `I1` 성인인증 / `I4` 지식재산 | 정책 문구 | 정책 응답 |

**Siren `I2`가 이 모델군을 도입하는 가장 큰 명분이다.** 우리가 손으로 만들려던 TIER-A 분류기를 F1 0.926의 학습된 모델이 대체한다. 자체 구축 대비 수개월 절약.

### 2.2 반드시 지켜야 할 제약 3개

**(1) 컨텍스트 비인식 → 재작성된 질의를 넣어라**

세 모델 모두 단일 발화 분류기다. 멀티턴에서 이런 일이 생긴다.

```
turn 1  "제가 고혈압 약을 먹고 있어요"           -> SAFE (사실 서술)
turn 2  "그럼 이거 같이 먹어도 되나요?"           -> SAFE (지시어뿐, 위험 신호 없음)
        ...실제 의미: 약물 상호작용 질의 = TIER-A  <- 놓친다
```

대응: **질의 정규화(Q) 이후의 self-contained query를 G2에 투입.** 위 예는 재작성 후 "고혈압 약과 OO를 함께 복용해도 되는지"가 되어 `I2`로 잡힌다.

**(2) 재작성 전 원문도 검사해라 (이중 검사)**

재작성 LLM이 공격을 세탁할 수 있다. 그래서 L1은 **원문에**, L3은 **재작성 결과에** 적용한다.

```
원문      -> G1 (prompt/safeguard)   : 공격은 원문 형태에서 잡아야 한다
재작성문  -> G2 (siren)              : 의도는 정규화 후에 잡아야 한다
재작성문  -> G1 재투입 (경량)         : 세탁 방지
```

**(3) recall 0.748을 전제로 설계해라**

prompt 모델은 precision 0.968 / recall 0.748이다. 즉 **오탐은 거의 없고(운영에 안전), 미탐이 25%**다. 단독 방어 불가.

보완 3종:
- 시스템 프롬프트를 컨텍스트에서 물리적으로 분리 (프롬프트에 정책 원문을 넣지 않음 → 리킹해도 잃을 게 없음)
- 검색 문서를 "데이터"로 명시 태깅하고 문서 내 지시문 무시 규칙 (간접 인젝션 — 내부 문서에 섞여 있을 수 있다)
- L6 출력 검증이 결과적으로 인젝션 성공을 차단 (근거 밖 내용이면 어차피 폐기됨)

### 2.3 임계값 튜닝

라벨만 쓰지 말고 첫 토큰 로짓에서 확률을 뽑는다.

```python
out = model(input_ids)                      # max_new_tokens=1
logits = out.logits[0, -1]
p_unsafe = softmax(logits)[unsafe_token_ids].sum()

if p_unsafe >= tau_block:   BLOCK
elif p_unsafe >= tau_warn:  DEGRADE   # 생성 허용, 단 verbatim만 / 검증 강화
else:                        PASS
```

`tau_block`, `tau_warn`을 **우리 골든셋으로 캘리브레이션**한다. Kakao의 내부 테스트셋 기준 수치는 병원 도메인에서 그대로 재현되지 않는다.

특히 검증할 경계 케이스:

```
"MRI 검사 전에 금식해야 하나요?"      -> I2? (안내여야 함. 과탐지면 커버리지 사망)
"제 검사 결과 수치가 정상인가요?"      -> I2 (맞음)
"당뇨 환자도 이 검진 받을 수 있나요?"  -> 경계. 병원과 합의 필요
"소아과 진료시간 알려주세요"          -> SAFE (당연)
```

### 2.4 과탐지 완화: 승인 인텐트 화이트리스트

Siren은 범용 모델이라 병원 안내 질의를 `I2`로 과탐할 수 있다. 완화 규칙:

```
if siren == I2:
    if 도메인_인텐트 in guard.intent_whitelist
       and 도메인_인텐트_confidence >= whitelist.min_confidence:
        -> I2 무시, TIER-B 진행 (단 verbatim 강제 + 검증 강화)
    else:
        -> TIER-A 차단
```

**이 완화 규칙은 병원 승인 사항이다.** 화이트리스트에 무엇이 들어가는지가 곧 "생성형이 답해도 되는 범위"의 합의문이 된다. `guard.intent_whitelist.approved_by`에 승인자를 남긴다.

### 2.5 결합 규칙과 순서

```
default        OR-차단 (하나라도 UNSAFE면 차단) — 안전 우선
early exit     규칙 응급 매처가 히트하면 모델 호출 없이 즉시 인터럽트
skip           TIER-C(인사·앱사용법)로 확정되면 siren 호출 생략 (지연 절감)
degrade        p_warn 구간은 차단하지 않고 verbatim-only 모드로 강등
fail-closed    모델 타임아웃(150ms 초과) -> 생성 포기, 시나리오 폴백
```

## 3. 규칙 층 상세

### L0 입력 위생

| 항목 | 처리 |
|---|---|
| 유니코드 정규화 | NFKC, 제로폭 문자(U+200B~D, U+FEFF) 제거 |
| 인코딩 우회 | base64/hex 유사 긴 토큰 탐지 → 디코딩 후 재검사 또는 차단 |
| 반복 폭탄 | 동일 문자/구 200자 초과 반복 → 절단 |
| 길이 | 사용자 발화 1000자 상한 |
| PII 마스킹 | 주민번호, 전화, 환자번호, 계좌, 카드, 이메일, 이름+생년 조합 |

PII는 **저장 전·LLM 전송 전 양쪽에서** 마스킹한다. `ops.turn`에는 마스킹본과 원문 해시만 남긴다.

### L2 응급 매처 (규칙이 모델보다 앞)

```
recall 우선 설계. 오탐(false positive)을 허용한다.
- 흉통, 가슴이 아파, 숨이 안 쉬어져, 호흡곤란, 의식이 없어, 쓰러졌,
  마비, 말이 어눌, 경련, 발작, 피가 멈추지 않, 약을 다 먹었, 죽고 싶,
  자해, 극단적 선택 ...
액션: 파이프라인 즉시 종료 + 119/응급실 안내 (+자해 표현 시 정신건강 상담 1393)
```

응급을 놓치는 비용이 오탐 비용보다 압도적으로 크다. 임계를 낮게 잡는다.

### L6 검증 규칙

| 검사 | 방식 | 실패 시 |
|---|---|---|
| 숫자·시간·금액·연락처 | **원문/SQL 결과와 문자열 exact match** | 즉시 폐기 (재생성 없음) |
| 금칙 표현 | 정규식 (`괜찮습니다`, `문제없습니다`, `~해도 됩니다`, `보통 ~합니다`) | 재생성 1회 |
| citation 유효성 | chunk_id 존재 + 해당 청크가 문장을 지지 | 재생성 1회 |
| entailment | claim 분해 → 근거 대조 (지지/모순/무관) | 무관·모순 1개라도 → 재생성 1회 |
| 출력 유해성 | safeguard-8b 재적용 | 폐기 |

숫자 검사에 재생성을 주지 않는 이유: 숫자를 틀리는 건 근거 오독이므로 재시도해도 같은 실패가 반복된다. 즉시 verbatim 폴백이 낫다.

## 4. 감사 로그 설계

`guard.decision_audit` 한 턴 예시:

```
turn_id  stage  decision  label       score  model                     latency
1042     G0     pass      -           -      rule:v3                   8ms
1042     G1     pass      SAFE        0.02   safeguard-prompt-2.1b     41ms
1042     G1     pass      SAFE        0.01   safeguard-8b              88ms
1042     Q      pass      -           -      claude-*/prompt:qnorm-v2  310ms
1042     G2     pass      SAFE        0.11   safeguard-siren-8b        95ms
1042     R0     miss      -           0.62   embed:bge-m3              44ms
1042     CRAG   round1    AMBIGUOUS   -      grader:crit-v4            290ms
1042     CRAG   round2    CORRECT     -      grader:crit-v4            520ms
1042     GEN    pass      -           -      claude-*/prompt:gen-v7    980ms
1042     G5     pass      -           -      verify:v5                 470ms
1042     OUT    answer    -           -      corpus:2026-08-19         -
```

이 로그로 답할 수 있어야 하는 질문
- "이 답변의 근거 문서와 개정일은?" → citations + corpus_version
- "왜 차단됐나?" → label + score
- "임계값을 0.7로 내리면 무엇이 바뀌나?" → score 분포 재집계
- "3개월 전 답변을 재현할 수 있나?" → 전 버전 스탬프

## 5. 실패 모드와 대응

| 실패 | 증상 | 대응 |
|---|---|---|
| 가드레일 과탐지 | 정상 질의가 TIER-A로 차단, 커버리지 붕괴 | 화이트리스트 + 임계 상향, 골든셋 재캘리브레이션 |
| 가드레일 미탐 | 의료 판단 질의에 생성 응답 | L6 금칙어 + entailment가 2차 차단. TIER-A leak은 릴리즈 차단 사유 |
| 간접 인젝션 | 내부 문서에 삽입된 지시문 실행 | 문서 데이터 태깅 + 지시문 무시 규칙 + L6 |
| 검증기 오류 | entailment 판정이 틀려 정상 답변 폐기 | over-abstain 지표로 추적, judge-사람 일치율 모니터 |
| GPU 장애 | 가드레일 호출 실패 | **fail-closed** → 시나리오 전용 모드로 자동 강등 (기존 챗봇과 동일 동작) |
| 모델 버전 변경 | 답변 성향이 조용히 바뀜 | 골든셋 회귀 필수, 버전 스탬프 |

> 마지막 줄이 중요하다. GPU가 죽으면 시스템은 **현재 운영 중인 시나리오 챗봇과 정확히 같은 동작**으로 강등된다. 가용성 리스크가 0이라는 뜻이고, 이게 발주처 설득의 마지막 조각이다.
